## Ветки и ревью

**Ветка + PR на каждый инкремент.** Инкремент — один осмысленный кусок: правка спеки, одна функция с тестами, одно исправление.

В `main` напрямую не коммитим. PR смотрится глазами до мерджа.

**Имя ветки:** `<тип>/<краткое-описание>` в kebab-case.

| Тип | Когда |
|---|---|
| `feat` | Новая функциональность: команда, ступень отбора, режим |
| `fix` | Исправление поведения |
| `refactor` | Перестройка без смены поведения |
| `test` | Только тесты |
| `docs` | Спека и документация |
| `chore` | Тулинг, зависимости, CI |

Примеры: `docs/rubrics-and-style-profile`, `feat/style-profile`, `fix/quartz-lazy-import`.

**Мерджим сквошем** (на GitHub — «Squash and merge»). Один PR — один коммит в `main`. Возня внутри ветки в историю не попадает, откат инкремента — revert одного коммита.

Исключение — rebase, если в PR несколько независимых кусков, которые нужно откатывать по отдельности. Обычно это значит, что PR стоило разбить на два.

## Спека и код расходятся

**При любом расхождении — сначала спросить.** Не «обойти и рассказать потом», не «поправить на своё усмотрение». Расхождение может означать ошибку в спеке, а может — то, чего не учли при планировании; разница видна только автору.

**Спека правится сразу**, а не копится до удобного момента. Правка идёт тем же флоу: отдельная ветка `docs/…`, PR, мердж. Если правка спеки нужна для работы кода, её PR мерджится первым — иначе код ссылается на то, чего в спеке ещё нет.

Смена решения, а не уточнение детали, — новая строка в §13 «Ключевые решения» SPEC с рассмотренными альтернативами.

## Тесты

**Тесты пишем обязательно**, через TDD: тест → падение → код → прохождение. Инкремент без тестов не мерджится.

- `uv run pytest` — юнит-тесты: Photos и Claude заменены заглушками (`tests/fakes.py`), Vision, ImageIO и AVFoundation настоящие.
- Интеграционные тесты на реальной Photos (маркеры `integration`, `cloud`) запускает пользователь в Terminal — у процесса Claude нет доступа к Photos. Как — в [tests/integration/README.md](tests/integration/README.md).
- Платные вызовы Claude API в тестах — только в тестах с маркером `cloud`.

## Секреты

Ни один ключ не попадает в репозиторий и в конфиги проекта. Ключ Claude API берётся из `ANTHROPIC_API_KEY` или профиля `ant auth login`.
