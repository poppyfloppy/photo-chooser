# Photo Chooser — SPEC

- **Статус:** Draft, на ревью
- **Дата:** 2026-11-01
- **Платформа:** macOS 26 (Tahoe), Apple Silicon

## 1. Проблема

После путешествий остаётся очень много фотографий. Отбирать их вручную тяжело, процесс затягивается и сходит на нет, а Instagram (лента и stories) так и не ведётся.

## 2. Цель

CLI-приложение для macOS, которое по альбому из Photos и заданным темам формирует **шорт-лист** лучших кадров, разложенный на кандидатов для **ленты** и для **stories**. Финальный выбор делает пользователь. Отобранные кадры дальше обрабатываются в другом инструменте.

Приоритеты при компромиссах: **качество отбора > время > цена**.

## 3. Сценарий использования

1. После поездки пользователь собирает фото поездки в альбом в Photos (~1000 фото).
2. Описывает темы в `trip.yaml` (или задаёт одну тему аргументами CLI): по содержанию («пирамиды, сфинкс»), по интервалу времени («14 марта, 05:00–12:00») или по обоим признакам.
3. Запускает `photo-chooser run trip.yaml`.
4. Получает директорию с копиями оригиналов: для каждой темы `feed/` и `stories/`, файлы пронумерованы по рангу, рядом `report.md` с причинами выбора.
5. Просматривает шорт-лист в Finder, выбирает финальные кадры и обрабатывает их в своём инструменте.

## 4. Scope

**В scope (MVP):**
- CLI без GUI.
- Чтение альбома Photos, включая оригиналы в iCloud («Оптимизация хранилища»).
- Фото: HEIC, JPEG, Live Photo, RAW (в том числе пары RAW+JPEG/HEIC).
- Темы по содержанию кадра (текстовый запрос на любом языке) и/или по интервалу времени.
- Отсев мусора и дублей, ранжирование, раскладка на ленту и stories.
- Копирование оригиналов в отдельную директорию и отчёт с короткой причиной выбора.
- Выбор модели Claude и режим без облака для дешёвой и бесплатной отладки.

**Вне scope:**
- Обработка кадров (перспектива, горизонт, баланс белого и т. п.) — пользователь делает её сам в другом инструменте.
- Видео.
- Любая запись в Photos: альбомы, метки, правки, избранное.
- Публикация в Instagram, подписи, хэштеги.
- GUI.
- Геотеги как признак темы: метка в геотеге может быть некорректной.

## 5. Функциональные требования

### FR-1. Входные данные

- **FR-1.1.** Источник — один альбом Photos, указанный по имени. Общие (shared) альбомы не поддерживаются (см. §8).
- **FR-1.2.** Тема задаётся полями:
  - `name` — имя темы, обязательно;
  - `query` — что искать в кадре, текст на любом языке;
  - `from` / `to` — интервал времени.

  Нужен хотя бы один из признаков: `query` или интервал. Если указаны оба, кадр должен удовлетворять обоим.
- **FR-1.3.** Интервал времени трактуется в **местном времени съёмки**, то есть в часовом поясе, который Photos хранит для каждого фото. Если у фото нет часового пояса, используется системный, и это отмечается в отчёте.
- **FR-1.4.** Тема только с интервалом (например, «День 3») означает, что все кадры интервала релевантны и ранжируются только по качеству.
- **FR-1.5.** Один кадр может попасть в несколько тем одного запуска: каждая тема обрабатывается независимо. Внутри одной темы кадр попадает либо в ленту, либо в stories, но не в оба списка.

### FR-2. Типы медиа

- **FR-2.1.** Учитываются фото: HEIC, JPEG, Live Photo, RAW/ProRAW. Видео игнорируются.
- **FR-2.2.** Пара RAW + JPEG/HEIC считается одним снимком. В шорт-лист копируются **оба** файла пары с одинаковым префиксом ранга.
- **FR-2.3.** Live Photo см. FR-5.

### FR-3. Конвейер отбора

Для каждой темы:

1. **Чтение альбома** — список снимков с метаданными. Для анализа используются локальные превью, которые Photos держит на Mac даже при «Оптимизации хранилища».
2. **Отсев мусора** (общий для всех тем, считается один раз):
   - скриншоты и «утилитарные» кадры (документы, чеки) по флагу Apple Vision;
   - сильный смаз;
   - полностью пересвеченные или чёрные кадры.

   Порог мягкий: отсекается только явный брак, потому что stories допускают изъяны.
3. **Дубли и серии** (общие для всех тем). Похожие кадры, снятые близко по времени, объединяются в кластер по визуальному отпечатку Vision и времени съёмки. Дальше идёт один представитель кластера — лучший по локальной оценке качества.
4. **Фильтр темы:**
   - по интервалу времени (FR-1.3);
   - по содержанию: сходство кадра с текстом `query` по мультиязычной модели «изображение–текст» (CLIP/SigLIP-класса), отсечение по порогу.
5. **Локальная оценка качества** — комбинация эстетической оценки Vision, оценок качества, уже посчитанных Photos (если доступны), резкости и качества лиц. Берутся топ-`candidates_per_theme` кандидатов.
6. **Оценка Claude** (в режиме без облака пропускается, см. FR-10.2). Кандидаты отправляются группами вместе с описанием темы. По каждому кадру возвращается:
   - соответствует ли кадр теме;
   - сила кадра для **ленты** (композиция и визуал), шкала 1–10;
   - пригодность для **stories** (люди и эмоции, интересное в контексте темы, о чём стоит рассказать; изъяны допустимы), шкала 1–10;
   - короткая причина на языке темы.

   Кадры, которые Claude счёл не соответствующими теме, исключаются. Для темы только с интервалом (FR-1.4) эта проверка не применяется.
7. **Раскладка** (FR-4).
8. **Live Photo** из итоговых списков обрабатываются по FR-5.
9. **Экспорт** (FR-6).

### FR-4. Лента и stories

- **FR-4.1. Лента:** до `shortlist.feed` кадров (по умолчанию 20) с наибольшей оценкой «лента» и не ниже порога `min_feed_score`. Ориентация не важна.
- **FR-4.2. Stories:** до `shortlist.stories` кадров (по умолчанию 40) из оставшихся, с оценкой «stories» не ниже порога `min_stories_score`. Этот порог ниже порога ленты. Порядок: сначала все подходящие **вертикальные** кадры по убыванию оценки, затем горизонтальные (квадратные идут вместе с горизонтальными).
- **FR-4.3.** Если подходящих кадров меньше лимита, в шорт-лист кладётся столько, сколько нашлось. Недобор мусором не заполняется, в отчёте указывается, сколько кадров не хватило.

### FR-5. Live Photo

- **FR-5.1.** Live Photo рассматривается как короткая анимация. Кандидаты на итоговый кадр — ключевой снимок и кадры видеочасти.
- **FR-5.2.** Кадры оцениваются локально: резкость, эстетика, качество лиц (открытые глаза).
- **FR-5.3.** У ключевого снимка разрешение выше, поэтому кадр видеочасти выбирается, только если он **явно** лучше: превосходит ключевой снимок на величину `live_frame_margin` из конфига.
- **FR-5.4.** Если выбран ключевой снимок, копируется его оригинал (HEIC/JPEG). Если выбран кадр видео, он сохраняется в **TIFF** (без потерь), в него переносятся дата и геоданные из оригинала, имя файла получает суффикс `_live-frame`. В отчёте указывается, что разрешение кадра ниже оригинала.
- **FR-5.5.** Видеочасть скачивается из iCloud только для Live Photo, попавших в итоговые списки.

### FR-6. Результат

- **FR-6.1.** Каждый запуск пишет в новую директорию и ничего не перезаписывает:

  ```
  <output_dir>/<альбом>/<YYYY-MM-DD_HHMM>/
    <тема>/
      feed/01_IMG_4521.HEIC
      feed/02_IMG_4533.DNG
      feed/02_IMG_4533.JPG
      stories/01_IMG_4610_live-frame.tiff
      report.md
  ```

- **FR-6.2.** Копируются **оригиналы**, без правок, сделанных в Photos. Двузначный префикс в имени — ранг внутри списка.
- **FR-6.3.** `report.md` на тему содержит:
  - шапку: модель (или «без облака»), `effort`, версия промпта — чтобы прогоны на разных моделях можно было сравнивать;
  - таблицу: ранг, файл(ы), лента или stories, оценка, ориентация, пометки (пара RAW, кадр из Live Photo, нет часового пояса), короткая причина выбора;
  - сводку: сколько снимков прочитано, отсеяно как мусор, схлопнуто как дубли, прошло фильтр темы, отправлено в облако; стоимость запуска и накопленная стоимость по альбому; недобор по FR-4.3; пропущенные снимки с причиной.

### FR-7. CLI

```
photo-chooser albums                     # список альбомов Photos
photo-chooser run trip.yaml              # все темы из файла поездки
photo-chooser run --album "Египет 2026" --theme "Гиза" --query "пирамиды, сфинкс" \
                  [--from "2026-03-12 06:00" --to "2026-03-12 14:00"]
photo-chooser run ... --dry-run          # только локальные этапы + оценка стоимости
photo-chooser run ... --max-cost 8       # разово поднять лимит бюджета
photo-chooser run ... --model claude-sonnet-5-5   # модель Claude для этого запуска
photo-chooser run ... --no-cloud         # без Claude: только локальные оценки, бесплатно
```

- **FR-7.1.** `--dry-run` выполняет локальные этапы 1–5, выводит число кандидатов по темам и оценку стоимости облачного этапа. Он не обращается к Claude и ничего не копирует.

### FR-8. Конфигурация

Общий конфиг `~/.config/photo-chooser/config.yaml`:

```yaml
output_dir: ~/Pictures/photo-chooser
shortlist:
  feed: 20
  stories: 40
cloud:
  model: claude-haiku-5-5          # на время отладки; прод-модель фиксируется по §12
  effort: medium                   # для прод-модели подбирается по §12
  pricing:                         # $ за 1 млн токенов (вход / выход), для оценки стоимости
    claude-haiku-5-5:  {input: 0.10, output: 0.50}
    claude-sonnet-5-5: {input: 2.00, output: 10.00}
    claude-opus-5-5:   {input: 4.00, output: 20.00}
  max_cost_usd_per_album: 5.0      # лимит накопленной стоимости по альбому
  candidates_per_theme: 100
  preview_long_side_px: 1024
  group_size: 20
thresholds:                        # значения по умолчанию подбираются в spike
  junk_blur: …
  duplicate_distance: …
  theme_relevance: …
  min_feed_score: …
  min_stories_score: …
  live_frame_margin: …
```

Файл поездки `trip.yaml`:

```yaml
album: "Египет 2026"
themes:
  - name: Гиза
    query: "пирамиды, сфинкс, верблюды на фоне пирамид"
  - name: Абу-Симбел
    query: "храм с колоссами Рамзеса"
    from: 2026-03-14 05:00
    to:   2026-03-14 12:00
  - name: День 3
    from: 2026-03-15 00:00
    to:   2026-03-15 23:59
```

Ключ Claude API в конфиге не хранится. Он берётся из `ANTHROPIC_API_KEY` или из профиля `ant auth login`. В режиме `--no-cloud` ключ не нужен.

### FR-9. Бюджет и кэш

- **FR-9.1.** Перед облачным этапом рассчитывается оценка стоимости. Если **накопленная стоимость по альбому + оценка** превышает `max_cost_usd_per_album`, запуск останавливается до отправки чего-либо в облако и выводит оценку. Разово поднять лимит можно флагом `--max-cost`.
- **FR-9.2.** Фактическая стоимость (по `usage` ответов API) записывается в кэш и в отчёт.
- **FR-9.3.** Кэш (SQLite, `~/Library/Caches/photo-chooser/`):
  - локальные признаки хранятся по снимку (UUID Photos);
  - оценки Claude хранятся по ключу «снимок × тема (хэш name+query+интервал) × модель × версия промпта».

  Повторный запуск той же темы не платит за облако повторно и продолжает работу с места сбоя.

### FR-10. Выбор модели и режим без облака

- **FR-10.1. Выбор модели.** Модель Claude задаётся в `cloud.model` и переопределяется флагом `--model` на один запуск. Поддерживаются модели Claude с приёмом изображений; проверяются `claude-haiku-5-5`, `claude-sonnet-5-5`, `claude-opus-5-5`. Если для модели нет цены в `cloud.pricing`, запуск останавливается до отправки в облако: без цены нельзя проверить бюджет (FR-9.1).
- **FR-10.2. Режим без облака** (`--no-cloud`). Этап 6 конвейера пропускается, Claude не вызывается, стоимость $0. Назначение режима — бесплатная отладка механики (чтение альбома, отсев, дубли, фильтр темы, раскладка, экспорт, отчёт), а не качество отбора. Правила:
  - соответствие теме определяется только локальной моделью;
  - лента — топ-`shortlist.feed` по локальной оценке качества;
  - stories — следующие `shortlist.stories` по локальной оценке, сначала вертикальные, затем горизонтальные;
  - пороги `min_feed_score` и `min_stories_score` не применяются: они заданы в шкале оценок Claude;
  - причина в отчёте — составляющие локальной оценки (эстетика, резкость, лица).
- **FR-10.3. Отладка** идёт на `claude-haiku-5-5` и в режиме без облака.
- **FR-10.4. Выбор прод-модели** — прогоны одних и тех же тем на разных моделях с ручным сравнением `report.md` (§12). Кэш разделяет оценки по модели (FR-9.3), каждый прогон пишет в свою директорию (FR-6.1), поэтому прогоны не смешиваются. Сравнительные прогоны расходуют общий лимит альбома; при необходимости он поднимается флагом `--max-cost`.

## 6. Нефункциональные требования

| ID | Требование | Как проверяется |
|---|---|---|
| NFR-1 | Медиатека Photos не изменяется (только чтение) | В адаптере Photos нет методов записи. Интеграционный тест сравнивает состав альбома, число снимков и даты изменения до и после прогона |
| NFR-2 | Стоимость облачной части на альбом ~1000 фото ≤ $5 | Защита бюджета (FR-9.1) и фактическая стоимость в отчёте |
| NFR-3 | Качество: в топ-20 ленты ≥ 10 кадров, которые пользователь готов обработать и опубликовать; в 40 stories ≥ 20 пригодных | Ручная оценка пользователем на альбоме прошлой поездки |
| NFR-4 | Первый прогон альбома ~1000 фото ≤ 30 мин; повторный прогон той же темы ≤ 5 мин | Замер на альбоме прошлой поездки |

## 7. Архитектура

**Стек:** Python 3.12; доступ к Photos через `osxphotos`; Apple Vision и AVFoundation через `pyobjc`; мультиязычная модель «изображение–текст» работает локально; Claude API через официальный Python SDK `anthropic`.

**Модули** (пакет `photo_chooser`). Внешние системы спрятаны за интерфейсами:

| Модуль | Ответственность |
|---|---|
| `library` | Доступ к Photos **только на чтение**: список альбомов, снимки альбома (UUID, имя файла, дата с часовым поясом, тип: Live/RAW/пара, ориентация, путь к превью, оценки Photos), экспорт оригинала(ов) и видеочасти Live Photo с загрузкой из iCloud. Реализация `OsxPhotosLibrary`; интерфейс позволяет заменить её Swift-хелпером на PhotoKit |
| `vision` | Обёртки над Apple Vision: эстетическая оценка и флаг «утилитарный», визуальный отпечаток, качество лиц |
| `analysis` | Отсев мусора, кластеры дублей, соответствие теме (эмбеддинги изображений и текста), локальная оценка качества, выбор кадра Live Photo |
| `judge` | Claude: формирование групп, запрос со структурированным ответом (JSON-схема), оценка стоимости, защита бюджета |
| `select` | Чистая логика раскладки на ленту и stories: по оценкам Claude (FR-4) или по локальным оценкам в режиме без облака (FR-10.2) |
| `export` | Копирование оригиналов, сохранение кадра Live Photo в TIFF с метаданными, `report.md` |
| `cache` | SQLite-кэш признаков, оценок и учёта стоимости |
| `config` / `cli` | Загрузка и валидация `config.yaml` / `trip.yaml`, команды CLI |

**Поток данных:**

```
альбом → снимки + превью → [мусор] → [кластеры дублей] → признаки (кэш)
  └─ для каждой темы: [интервал] → [релевантность query] → [локальная оценка] → топ-N
       → Claude группами (кэш) → select → Live Photo → export + report.md
```

## 8. Внешние ограничения

- macOS 26 (Tahoe), Apple Silicon.
- Медиатека Photos с включённой «Оптимизацией хранилища»: оригиналы лежат в iCloud и скачиваются по требованию.
- `osxphotos` 0.77.x: по его README, на macOS 26 проводилось только ограниченное тестирование; общие (shared) альбомы на macOS 26 не читаются.
- Терминалу, из которого запускается приложение, пользователь один раз выдаёт доступ к Photos (и при необходимости Full Disk Access). Приложение проверяет доступ и подсказывает, что сделать.
- Видеочасть Live Photo имеет заметно меньшее разрешение, чем ключевой снимок.
- Для облачного этапа нужен ключ Claude API, использование платное.

## 9. Интеграции

### Photos (через osxphotos)

- Чтение базы Photos в режиме только чтения.
- Экспорт оригиналов, обеих частей пары RAW и видеочасти Live Photo с загрузкой из iCloud.
- Побочный эффект загрузки: Photos может временно хранить скачанный оригинал на Mac. Содержимое медиатеки (правки, альбомы, метаданные) при этом не меняется.
- Ошибка загрузки обрабатывается так: повтор до 3 раз, затем снимок пропускается, на его место встаёт следующий кандидат, в отчёт записывается причина.

### Apple Vision / AVFoundation (через pyobjc)

- Vision даёт эстетическую оценку с флагом «утилитарный кадр», визуальный отпечаток для поиска дублей и качество лиц.
- AVFoundation извлекает кадры видеочасти Live Photo.

### Локальная модель «изображение–текст»

- Мультиязычная, чтобы запрос можно было писать на любом языке.
- Конкретная модель выбирается в spike по качеству на фото пользователя.
- Эмбеддинги изображений кэшируются.

### Claude API

- **Модель:** задаётся в конфиге или флагом `--model` (FR-10). Отладка — на `claude-haiku-5-5`, прод-модель выбирается по §12.
- **Вход:** превью кадров с длинной стороной `preview_long_side_px` (по умолчанию 1024), группы по `group_size` (по умолчанию 20) с описанием темы и общей рубрикой оценки. Кандидаты распределяются по группам так, чтобы в каждой был разброс локальных оценок.
- **Выход:** структурированный JSON по схеме: `id`, `matches_theme`, `feed_score`, `stories_score`, `reason`.
- **Оценка стоимости:** перед отправкой, по подсчёту токенов.
- **Ошибки:**
  - повторы средствами SDK;
  - обработка `stop_reason: refusal`;
  - если тема всё равно не обработана, остальные темы продолжаются, а отчёт её помечает.
- **Ориентир стоимости** при ~100 кандидатах на тему (уточняется в spike):

  | Модель | ≈ за тему | Тем в лимит $5 |
  |---|---|---|
  | `claude-haiku-5-5` | ~$0.03 | без ограничений на практике |
  | `claude-sonnet-5-5` | ~$0.6 | ~8 |
  | `claude-opus-5-5` | ~$1–1.5 | 3–4 |

  Цена Haiku 5.5 действует для запросов до 100K токенов; запрос с группой из 20 превью укладывается в этот предел.

## 10. Тестирование

- **Юнит-тесты (pytest)**, Photos и Claude заменены заглушками:
  - валидация конфигов и тем;
  - интервалы времени и часовые пояса;
  - кластеризация дублей на синтетических векторах;
  - правила раскладки (FR-4): пороги, порядок вертикальные → горизонтальные, недобор;
  - нумерация и имена файлов, пары RAW, суффикс `_live-frame`;
  - генерация `report.md`;
  - защита бюджета и кэш;
  - выбор модели и остановка для модели без цены в `pricing`; режим без облака (FR-10.2).
- **Интеграционный тест** на тестовом альбоме Photos (~30 фото). Альбом содержит известные случаи: серию дублей, скриншот, смазанный кадр, Live Photo, пару RAW+JPEG, кадры двух разных «тем». Тест проверяет FR-3–FR-6 и NFR-1.
- **Оценка качества** (NFR-3, NFR-4) — прогон на альбоме прошлой поездки с ручной оценкой пользователя.

## 11. Первый шаг реализации — spike

Цель — проверить предпосылки до основной разработки. На медиатеке пользователя (macOS 26, «Оптимизация хранилища») проверить:

1. `osxphotos` читает альбом и метаданные: дату с часовым поясом, признаки Live/RAW/пары.
2. Локальные превью доступны без загрузки из iCloud.
3. Загружаются из iCloud и экспортируются оригиналы, обе части пары RAW и видеочасть Live Photo.
4. Доступны ли оценки качества Photos на macOS 26.
5. Через `pyobjc` работают эстетическая оценка Vision и визуальный отпечаток.
6. Выбирается мультиязычная модель «изображение–текст»: сравнение 2–3 кандидатов на нескольких запросах по фото пользователя.
7. На `claude-haiku-5-5` замеряется реальный расход токенов на один кадр и на одну группу. По результатам выбираются значения по умолчанию `candidates_per_theme`, `preview_long_side_px`, `group_size`.

**Критерий провала:** не выполняется пункт 1 или 3. Тогда модуль `library` переводится на Swift-хелпер с PhotoKit (решение D1, альтернатива C), остальное не меняется.

## 12. Выбор прод-модели

Выполняется после отладки, когда конвейер и промпт стабилизированы на `claude-haiku-5-5` и в режиме без облака.

1. Взять альбом прошлой поездки и 2–3 темы разного типа: по содержанию, по интервалу, смешанную.
2. Прогнать их на кандидатах в прод-модели: `claude-haiku-5-5`, `claude-sonnet-5-5`, `claude-opus-5-5`.
3. Пользователь сравнивает `report.md` прогонов по качеству (NFR-3) и стоимости (NFR-2). Время (NFR-4) учитывается третьим, по приоритету «качество > время > цена».
4. Победившая модель и подобранный для неё `effort` фиксируются в `cloud.model` и `cloud.effort`.

## 13. Ключевые решения

| ID | Решение | Рассмотренные альтернативы | Почему так |
|---|---|---|---|
| D1 | Python + osxphotos, доступ к Photos за интерфейсом `library` | (B) только Swift: PhotoKit, Vision, Core ML; (C) Python + Swift-хелпер для PhotoKit | Быстрее всего даёт рабочий результат; богатая экосистема ML; официальный SDK Claude есть для Python, для Swift нет. Риск osxphotos на macOS 26 проверяется spike, запасной путь — C |
| D2 | Гибрид: мусор, дубли, фильтр темы и предварительное ранжирование локально, финальная оценка — Claude по каждой теме отдельно; лимит $5 на альбом | Только локально; всё в облаке; оценка Claude один раз на фото без привязки к теме (~$3.5–4 за альбом, темы бесплатно) | Качество в приоритете: Claude сравнивает кадры в контексте темы. Стоимость контролируется лимитом и кэшем |
| D3 | Тема определяется по содержанию кадра и/или интервалу времени; геотеги не используются | Геотеги; геотег с запасным вариантом по содержанию | Метка в геотеге может быть некорректной |
| D4 | Результат — копии оригиналов в отдельной директории; Photos только на чтение | Альбом в Photos; только отчёт без файлов | Требование пользователя |
| D5 | Live Photo: выбирается лучший кадр анимации; кадр видео только если явно лучше ключевого; сохраняется в TIFF | Только ключевой снимок; ключевой снимок + кадр из видео рядом | Требование пользователя; запас и TIFF компенсируют меньшее разрешение видео |
| D6 | Модель Claude выбирается в конфиге или флагом; отладка на Haiku 5.5 и в режиме без облака; прод-модель выбирается сравнением отчётов прогонов | Фиксированная модель; бесплатная локальная мультимодальная модель (Ollama) для отладки; встроенная команда `compare` | Дешёвая и бесплатная отладка при одном провайдере. Ollama — вторая интеграция с иным поведением, результаты отладки на ней не переносятся на Claude. Для сравнения достаточно отчётов с моделью и стоимостью в шапке |

## 14. Принятые риски

| Риск | Последствие | Как смягчаем |
|---|---|---|
| osxphotos читает приватную базу Photos, на macOS 26 тестирование ограничено | Обновление macOS может сломать чтение | Spike (§11); адаптер `library` заменяем на PhotoKit |
| Оценки Claude в разных группах откалиброваны неидеально | Ранжирование между группами неточное | Общая рубрика, перемешивание групп по локальной оценке, при равенстве — локальная оценка |
| Ориентир стоимости грубый | Превышение NFR-2 | Замер в spike; защита бюджета останавливает запуск до отправки |
| Поиск по содержанию пропускает часть подходящих кадров | Неполный шорт-лист по теме | Настраиваемый порог; `--dry-run` показывает число кандидатов; в теме можно задать интервал |
| Загрузка оригиналов из iCloud медленная | Превышение NFR-4 | Загружаются только кадры итоговых списков; анализ идёт по локальным превью |
| Скачанные оригиналы занимают место на Mac | Рост занятого места на диске | Загружается только шорт-лист (≤ 60 снимков на тему) |
| Промпт, отлаженный на Haiku 5.5, ведёт себя иначе на прод-модели | Качество на проде ниже ожидаемого | Сравнительные прогоны на всех кандидатах в прод-модели (§12) до фиксации модели |
