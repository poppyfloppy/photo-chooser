## Дальше

1. **Версия 0.5.1 — оптимизация стоимости без роста времени.** Брейнсторм прошёл 2026-11-05, спека — PR #34. Дальше — план, код по TDD и проверочный прогон шести тем на Opus против `2026-11-03_0133`: стоимость, токены, время, доля совпавших кадров постов; расхождения смотрит пользователь. Что решено:
   - пакетный режим удаляется (FR-12, D16);
   - настройки ступеней — секции `cloud.screen` и `cloud.judge`: модель, `effort`, `preview_px` (D18);
   - вторая ступень и сборка — превью 768 px и `effort` high, первая ступень без изменений;
   - `effort` и размер превью входят в ключ кэша;
   - советы по кадрированию пишет сборка, только для кадров постов (D10);
   - токены и время ступеней — в отчёте.

   Исходные идеи брейнсторма — для истории:
   - **Время пакета** — это очередь API без гарантий (ждали больше часа).
     - Вариант: ждать пакет не дольше N минут, потом отменить и досчитать синхронно. Отменённые запросы не оплачиваются, обработанные — со скидкой.
     - Вариант: пакетом только сборку или только вторую ступень.
   - **Синхронный режим с кэшем и более дешёвой моделью.** Sonnet 5.5 примерно вдвое дешевле Opus: три темы — $1.16 за несколько минут. Качество Sonnet на 0.5 не оценивалось.
   - **Меньше входных токенов**, это и время, и деньги:
     - превью меньше 1024 px;
     - `cloud.candidates_per_theme` меньше 100;
     - меньше или мельче скриншоты-образцы (4 шт. по 1568 px — основная часть мета-блока в ~9.5 тыс. токенов);
     - строже порог первой ступени.
   - **Параллельность синхронного режима.** `MAX_PARALLEL_REQUESTS = 3`; лимиты скорости организации.
   - **Строка хода пакета.** API, похоже, не отдаёт частичный ход, поэтому «готово 0 из N» выглядит зависанием. Предложено писать «в обработке, запросов N», пока нет реальных цифр. Это правка FR-7.2 и кода; пользователь ещё не решил.
